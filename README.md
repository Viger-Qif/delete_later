## Быстрый запуск

### Требования к Python

- Поддерживаются **Python 3.11–3.13** (рекомендуется 3.12/3.13).
- ⚠️ На **Python 3.14** `pip` может не найти готовые пакеты (`setuptools`, `wheel`, производные wheels) — используйте 3.11–3.13.
- Если `pip install` падает с сетевой ошибкой (таймаут, `Could not find a version`, блокировка PyPI), поставьте зависимости через зеркало:

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn
```

и/или смените сеть (мобильная точка доступа вместо корпоративной). `start.bat` / `start-demo.sh` при ошибке установки подсказывают эту команду.

### Windows — один файл

Дважды нажмите **`start.bat`**. Это единый установщик и запускатель. Рекомендуется Python 3.13; Python 3.12 также поддерживается. Установщик сам:

1. найдёт Python 3.13 или 3.12; если их нет и доступен `winget`, установит официальный Python 3.13;
2. создаст или проверит локальное `.venv`;
3. восстановит отсутствующий `pip` через `ensurepip`, а повреждённое окружение пересоздаст;
4. обновит `pip`, `setuptools`, `wheel` и скачает **все библиотеки** из `requirements.txt`;
5. создаст `.env` из `.env.example`, не перезаписывая уже настроенный `.env`;
6. запустит API, дождётся `/api/health` и откроет браузер.

Повторный запуск безопасен: зависимости снова проверяются через `pip`, а пользовательские настройки `.env` сохраняются. Логи установки и сервера находятся в `logs/setup.log` и `logs/server.log`.

`start-demo.bat` оставлен как совместимое имя для старых ярлыков и просто вызывает `start.bat`. Чтобы только настроить и запустить сервер без автоматического открытия браузера, используйте `start.bat --no-browser`.

Если в старой сборке появлялось `No module named pip`, просто запустите новый `start.bat`: удалять `.venv` или вручную менять номер Python больше не нужно. Подробности восстановления записываются в `logs/setup.log`.

### macOS / Linux

```bash
chmod +x start-demo.sh
./start-demo.sh
```

Приложение: http://127.0.0.1:8000/. Swagger: http://127.0.0.1:8000/docs.

### Docker — приложение + PostgreSQL

На Windows запустите `start-docker.bat`: он проверит Docker Desktop, соберёт контейнеры, дождётся `/api/health` и откроет браузер. Остановить контейнеры можно через `stop-docker.bat`. На Linux/macOS используйте `./start-docker.sh`.

Данные PostgreSQL сохраняются в volume `negotiation_lab_pgdata`. Для полного удаления базы: `docker compose down -v`.

## Справочник и RAG

В текущем контуре подключены RAG-чанки с устойчивыми ID, методикой, этапом, уровнем, связанными карточками и ссылкой на источник. В учебном контуре отдельно находятся SPIN-упражнения, очередь повторения, рефлексия и прогресс пользователя. BM25-поиск используется в генерации сценариев, ответах оппонента, подсказках Фиделины и итоговом анализе.

Проверить контур можно через:

- `GET /api/knowledge/status` — число карточек и упражнений;
- `GET /api/knowledge/search?q=...&scenario_id=...` — поиск с фильтрацией сценария;
- `GET /api/knowledge/entry/{id}` — карточка с метаданными и источником;
- `GET /api/knowledge/drills?method_id=spin` — упражнения по методике.

В итоговом анализе модель может вернуть `knowledge_refs`; ссылки проверяются по существующим ID и отображаются как переходы в справочник. Векторную БД пока не подключаем: сначала собираем реальные запросы и benchmark Recall@3/Recall@5, затем можно заменить внутренний BM25 без изменения API.
